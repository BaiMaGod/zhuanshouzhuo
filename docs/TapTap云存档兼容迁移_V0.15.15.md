# TapTap H5 云存档兼容迁移修复 V0.15.15

- 日期：2026-11-06
- 适用版本：0.15.15
- 适用范围：TapTap H5 正式包
- 核心原则：云端唯一权威；迁移前备份；只隔离不兼容的未完成盘面；永久进度不丢失。

## 问题复盘

V0.15.14 的云档校验把每一局未完成盘面都作为整份云存档的硬性条件。只要某个盘面的关卡修订号、手镯数量/布局、锁扣结构或盘面状态与当前构建不一致，`validateCloud` 就抛出 `Invalid run`，导致整份云存档被拒绝。通关记录、星级、道具等其他有效数据也无法恢复。

另外，TapTap 某些连接故障返回 `-1`，错误消息可能是 `Connection refused`。旧重试分类未将这类连接拒绝识别为临时网络故障。

## V0.15.15 修复内容

### 1. 云档分层校验

- 云档身份、版本、永久进度、经济数据、奖励数据、排行榜数据和盘面索引仍严格校验。
- 对每个未完成盘面单独校验，提供具体原因：关卡修订号变化、手镯布局变化、锁扣布局变化、盘面状态无效等。
- 仅在远端恢复流程中允许将不兼容的单局盘面隔离；正常本地待同步事务和写入仍使用严格校验。
- 锁扣结构比较改为规范化 JSON 比较，不再把对象属性顺序差异误判为结构变化。

### 2. 原始云档先备份，再迁移

- 下载后保留原始 JSON 文本。
- 如果发现不兼容盘面，先将原始文件写入 TapTap `USER_DATA_PATH`，文件名包含 archive UUID 和 fileId。
- 备份成功后才允许恢复清洗后的云档。
- 备份失败则保持云档恢复门禁，不替换本地缓存、不上传覆盖云端。
- 隔离单局盘面时保留永久进度、星级、道具、奖励记录及其他有效盘面。

### 3. 迁移结果作为待同步事务

- 清洗后的云档以云端 revision 为基准。
- 将迁移标记为新的 dirty revision，遵守 65 秒上传冷却，不在下载后直接覆盖云档。
- 上传成功后才确认新 revision；上传失败继续执行现有云同步阻断与核对流程。
- 玩家会收到迁移提示，明确列出受影响关卡及本机备份文件路径。

### 4. 临时连接故障自动重试

- 将 `-1 + Connection refused`、`ECONNREFUSED`、连接重置、网络离线、DNS 等识别为可重试故障。
- 沿用 5/15/30 秒退避重试，不快速循环请求。
- `Invalid run`、身份不匹配和永久结构错误不会被误判为网络错误，仍保持启动阻断并提供人工重试/诊断。

## 自动化回归

新增测试覆盖：

1. 单个旧 revision 盘面被隔离，永久成绩和其他有效盘面保留。
2. JSON 对象键顺序变化不再导致盘面误判。
3. 原始云档备份成功后才执行隔离。
4. 本地备份失败时不开放游戏、不替换或覆盖云端原档。
5. `Connection refused` 自动重试成功；普通 `Invalid run` 不会被误判为网络故障。

## 真机验收清单

- 使用真实 TapTap 账号升级安装 0.15.15，验证原有通关成绩、星星、签到和背包数据。
- 使用包含旧版未完成盘面的账号验证：仅不兼容的盘面被隔离，其余盘面与永久进度保留。
- 检查本地 `USER_DATA_PATH` 中的 `jade_recovery_<uuid>_<fileId>.json` 备份文件可读取。
- 在备份写入失败、断网、恢复网络等情况下确认游戏门禁与重试行为。
- 确认迁移后的云档遵守至少 65 秒写入间隔，且始终更新原 archive UUID，不创建重复存档。

自动化模拟测试不能替代真实 TapTap 容器、真实账号和真实云存档服务验收。
