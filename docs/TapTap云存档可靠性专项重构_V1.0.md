# 《转手镯消除》TapTap H5 云存档可靠性专项重构方案

- 方案版本：V1.0
- 状态：已确认，进入实施
- 优先级：P0
- 适用范围：TapTap H5 正式包
- 核心原则：**云端唯一权威、启动强制恢复、后台异步同步、失败强制暂停、本地仅保留待同步事务。**

## 1. 目标与边界

本专项解决云存档读取失败后误进游戏、老玩家进度恢复异常、同步失败后继续操作、本地 session 缓存无法安全续传、首次进入没有创建云档以及超时重试可能重复创建云档等问题。

TapTap H5 正式包采用严格云端权威模式：

1. TapTap 云存档是玩家进度的唯一权威来源。
2. 启动时必须成功读取并校验云档；新用户必须先成功创建第一份云档，才允许进入游戏。
3. 云存档接口不可用、读取失败、数据损坏、身份不匹配时，不允许进入游戏，也不允许降级为本地游戏。
4. 游戏过程中的云端上传在后台异步执行，上传进行中不锁定玩家操作。
5. 只有云端写入确认失败或结果无法确认时，才锁定所有会改变进度的操作并提示玩家。
6. 同步成功后自动解除锁定；本地缓存仅用于保留尚未确认的同步事务，不是独立存档来源。
7. Web 预览版可继续使用原有非 TapTap 行为；严格云端门禁必须由 TapTap H5 构建标记明确启用，不能仅凭运行时某个 SDK 方法是否存在推断目标平台。

## 2. TapTap 云存档频率限制

项目按 TapTap 小游戏/H5 云存档接口规则处理：

- `createArchive` 与 `updateArchive` 的写入频率限制共用。
- 两次写入请求至少间隔 65 秒，给平台每分钟限制留出安全余量。
- 不允许每次旋转、每次消除都直接调用云端写入接口。
- `getArchiveList`、`getArchiveData` 用于读取与核对；不得把读取操作误当作写入额度。
- 遇到频率限制错误（例如 `400001`）时，记录错误并等待冷却窗口，不得快速循环重试。
- 同一时间只允许一个云存档写入任务。

官方接口文档：
- [TapTap 小游戏云存档接入指南](https://developer.taptap.cn/minigameapidoc/dev/tutorial/open-capabilities/cloud-save-tutorial/)
- [TapTap 小游戏 API 文档](https://developer.taptap.cn/minigameapidoc/)

## 3. 启动与恢复状态机

### 3.1 老玩家

`BOOT → CHECK_CLOUD_CAPABILITY → GET_ARCHIVE_LIST → DOWNLOAD → VALIDATE → RECONCILE_PENDING_TXN → READY`

执行要求：

1. 启动后立即锁定游戏入口。
2. 获取当前 TapTap 容器用户的云存档列表。
3. 只筛选游戏固定 SLOT：`jade_save_v1`。
4. 找到存档后下载完整文件。
5. 校验 JSON、schema、关卡盘面、经济数据、奖励数据及存档身份。
6. 以云端 archive UUID 建立稳定的本地缓存命名空间。
7. 将云端数据作为权威基准，核对同一 archive UUID 下的本地待同步事务。
8. 只有云端恢复成功，且待同步事务已安全确认/补传或被判定为过期并丢弃后，才开放游戏。

### 3.2 新用户

TapTap 返回结构有效的空列表（例如 `saves: []`）代表正常的新用户，不是读取失败。

新用户流程：

`BOOT → GET_ARCHIVE_LIST → EMPTY → CREATE_INITIAL_ARCHIVE → VERIFY_CREATE → READY`

要求：

- 不导入旧访客缓存，不自动迁移其他账号或旧 session 的数据。
- 创建包含初始空进度的第一份云档。
- 创建成功必须返回可用的 archive UUID 与 fileId。
- 创建结果校验成功后，将本地缓存迁移到 `archive:<uuid>` 命名空间。
- 创建失败、超时或响应不完整时保持启动阻塞；不得把“空列表”当成已经完成初始化。
- 首次教学关卡只能在第一份云档创建成功后自动启动。

### 3.3 启动异常

以下任一情况均不得进入游戏：

- TapTap 云存档 API 缺失或初始化未完成。
- 获取列表失败、超时或响应结构错误。
- SLOT 存档下载失败。
- JSON 无法解析、schema 不兼容或数据校验失败。
- archive UUID/fileId 缺失。
- 存档身份无法验证。
- 待同步事务与云端基准版本冲突，且无法安全确认。

界面显示“云存档暂时无法读取”，提供“重新连接”和“退出游戏”。不得提供“继续本地游戏”“恢复本机进度后继续”或任何绕过云端门禁的入口。

## 4. 本地缓存与待同步事务

### 4.1 本地缓存的职责

本地缓存只用于：
- 保留云端上次确认后产生、尚未上传成功的完整最新状态。
- 保留同步事务的版本和基准版本。
- 在上传超时后判断服务器是否已经实际写入。
- 在应用意外退出后，恢复安全可续传的待同步事务。

本地缓存不能：
- 单独授权玩家进入游戏。
- 覆盖更高版本的云端存档。
- 从其他账号/session 自动导入进度。
- 在云档读取失败时成为离线游戏模式。

### 4.2 Revision 与 Base Revision

每次有效游戏状态变化都增加本地 `revision`，并保留该批待同步数据所基于的云端 `baseRevision`。

建议本地事务至少保存：

| 字段 | 用途 |
|---|---|
| `archiveUUID` | 事务所属云存档 |
| `baseRevision` | 产生待同步修改时，云端已确认的版本 |
| `revision` | 当前本机最新完整快照版本 |
| `snapshot` | 最新完整游戏进度 |
| `dirty` | 是否有尚未确认的修改 |
| `lastAttemptAt` | 最近一次云端写入请求时间 |
| `inFlightRevision` | 最近一次发起云端写入的快照版本 |
| `inFlightBaseRevision` | 该次上传快照所基于的云端版本 |
| `status` | 运行时派生状态，由 dirty、inFlightRevision 和云端连接状态共同决定，不单独持久化 |

云端快照的 `revision` 表示服务端已确认版本；云端不应携带本地 `dirty=true` 状态。

### 4.3 重启后的待同步事务核对

必须先成功读取云档，再处理本机缓存：

- 若云端 revision 等于本地 revision：视为上次写入已成功但客户端可能未记录回执，清除本地 dirty。
- 若本地 dirty=true，且本地 baseRevision 等于云端 revision，且本地 revision 更高：该事务基于当前云端版本，可在遵守 65 秒冷却后补传；补传成功前不进入游戏。
- 若云端 revision 等于本地 inFlightRevision，说明上一次上传快照很可能已在服务端提交、只是客户端未收到回执；先将该 in-flight revision 记为已确认，再保留并补传更高的本地 revision，不能因超时丢弃上传期间的新操作。
- 若云端 revision 高于本地事务的 baseRevision，或无法验证事务归属/基准版本：云端优先，本地事务不得覆盖云端；以云端快照重建本地缓存。
- 若本地缓存不存在或被系统清理：直接恢复云端最后一次确认的版本。
- 旧版本缓存没有可靠 baseRevision 时，不得猜测它可安全续传；按云端权威规则处理，并保留诊断信息。

## 5. 游戏过程中的异步同步

### 5.1 本地记录

以下操作改变游戏状态时，立即更新内存并持久化最新待同步快照，增加 revision：

- 手镯旋转、对齐和消除。
- 撤销。
- 提示/消除道具使用及奖励次数变化。
- 关卡通关、重开和局内盘面变化。
- 签到、背包及会影响云端进度的经济数据变化。

本地缓存写入不调用云端上传接口。

### 5.2 后台上传

- 距上次 `createArchive`/`updateArchive` 请求至少 65 秒后，上传最新完整快照。
- 上传过程中玩家继续操作，不锁定手镯、提示、撤销、动画或其他游戏功能。
- 一个上传任务只上传开始时固定的 revision 快照。
- 上传期间产生的新操作递增 revision，继续保留 dirty。
- 上传成功只确认本次快照 revision；若当前 revision 更高，仍保持 dirty，等待下一次允许写入的窗口。
- 上传成功后更新 archive UUID/fileId 与最后确认 revision。

### 5.3 同步失败

以下情况视为同步失败或结果不确定：

- 网络错误、平台 fail 回调。
- 上传超时。
- 返回结构缺失或无法确认 archive UUID/fileId。
- 频率限制错误。
- 服务器结果未知，无法判断写入是否成功。

失败后：

1. 立即设置全局 `cloudBlocked=true`。
2. 弹出“云存档同步异常”弹窗。
3. 禁止所有会改变进度的操作；不能通过返回首页、打开关卡图谱、重开或重新进入关卡绕过。
4. 不清除 dirty，不回滚覆盖最新本地快照。
5. 玩家点击“重新同步”后，先核对云端状态；只有确认同步成功后才解除阻塞。
6. 上传请求尚在进行时不锁定游戏；只有明确失败/超时后才锁定。

同步异常文案：

> 当前游戏进度尚未成功同步到云端，请检查网络连接后重试。为保护游戏进度，当前游戏操作已暂停。同步成功后即可继续游戏。

按钮：
- 重新同步
- 平台连接检查

## 6. 超时、重复创建与并发保护

上传超时不等于服务器一定没有写入。重试前必须重新读取云档列表：

1. 查询当前用户的 `jade_save_v1`。
2. 若此前创建请求已成功，找到现有 SLOT，下载并检查 revision，不得再次 create。
3. 若云端 revision 已达到本地待确认 revision，认定上次写入成功，更新本地确认状态。
4. 若 SLOT 存在但版本较低，使用该 UUID 更新，不得创建第二份 SLOT。
5. 只有新用户首次初始化、且有效列表确认没有 SLOT 时才允许 create。
6. 已经绑定 archive UUID 的活跃账号，如果后续列表暂时找不到该 SLOT，必须保持阻塞并继续核对；禁止创建替代云档。
7. 若云端版本比本机事务更新，云端优先，不得用旧快照覆盖。

同一运行实例禁止并发 `createArchive`/`updateArchive`；同一 archive UUID 的写入必须串行。

## 7. 身份与数据校验

- `tap.login` 返回的一次性 code 不作为长期账号 ID。
- 云档归属以 TapTap 容器云存档接口返回的 archive UUID/容器用户上下文为边界。
- 下载原始数据后先验证原始 owner/schema，再转换为本地 `archive:<uuid>` 命名空间。
- 必须先绑定正确 archive UUID，再执行本地/云端比较。
- 严格云端模式不自动调用 `importGuest`、`importRecovery`，不自动合并旧 session 数据。
- 云端快照是恢复依据；旧缓存不能因为 revision 数值更大就自动覆盖云端。
- 存档校验失败时不上传任何覆盖数据。

## 11. 验收标准

- TapTap H5 没有云档就不能进入游戏。
- 新用户必须先创建第一份云档。
- 老用户重启后正确恢复最后一次云端确认进度。
- 正常上传期间游戏操作不被锁定。
- 云端写入失败后立即暂停所有进度修改操作。
- 只有云端确认成功后才恢复游戏。
- 65 秒写入频率限制始终生效。
- 上传超时不会导致重复创建 SLOT。
- revision/baseRevision 不会错误确认未上传的新操作。
- 本地缓存永远不能覆盖更高版本云端存档。
- web 预览构建不被 TapTap 严格云端门禁误伤。
