## 0. 需求依据与优先级

本方案以用户已确认的要求为准：

1. 游戏名称统一为**《转手镯消除》**，不使用《玉环十镜》等旧称。
2. **签到图标固定在首页屏幕左边缘**；**背包图标固定在首页屏幕右边缘**；二者横向对称、同一高度，且**垂直位置略高于「开始游戏／第X关」主按钮**，不是夹在主按钮左右紧邻的位置。
3. 图标、签到页、背包页**必须沿用当前游戏的真实美术风格**；先检查仓库里的首页、图标、弹窗和素材，再制作或复用视觉资源，不能用通用现代手游 UI 替代。
4. 七日累计签到、道具领取入背包、背包永久存储、关卡内消耗、原有平台激励功能保留。
5. 首次启动直达教学关卡；**签到不得打断首启教学**。

实现优先级：用户本次确认 > 本文需求 > 当前代码约束 > 历史设计文档。与旧版本描述有差异时，按代码实况做兼容性整改，而非复制历史配置。

## 1. 设计目标、范围与边界

### 1.1 功能目标

- 提高次日与七日回访意愿，但不强制连续登录或制造断签焦虑。
- 为正式关卡提供可积累的提示和消除储备，缓解高难度关卡的卡点。
- 让签到、背包与现有免费提示、广告和分享激励组成**一套可解释的获取—存储—使用闭环**。
- 首页增加两个清晰入口，同时保持主按钮的第一视觉层级与盘面表现。

### 1.2 V1.0 包含

首页签到/背包入口；7天累计签到；当日领取和进度展示；两类道具（提示/消除）永久库存；奖励入账反馈；背包查看数量/说明；关内统一扣减；本地持久化、TapTap 云存档字段迁移及失败回退；Debug 兼容；必要埋点和验证用例。

### 1.3 V1.0 不包含

道具商店、付费礼包、补签、签到双倍广告、连续签到惩罚、背包扩容、交易/赠送、全新道具种类、金币或材料货币、直接在背包界面使用道具、额外的关卡 UI 常驻按钮。体力道具预留扩展点，不在本期强行上架。

│ 教学进度                      设置 │

│                                    │
│           玉盘 / 手镯展示          │

│                                    │

注意：图示只表明**相对位置**。两个图标不应移到「第X关」按钮左右紧邻位置，更不能排进图谱/教学那一行。

### 2.2 720 逻辑坐标候选（开发基线）

现有首页以 \`W=720\` 与动态 \`H\` 绘制。推荐建立一个「两侧快捷入口」布局函数，不写死手机 CSS 像素。

| 项目 | 建议初始值（逻辑坐标） | 约束 |
| --- | --- | --- |
| 左签到入口热区 | \`x=12,\; w=96\` | 贴近左边缘，允许安全边距调整 |
| 右背包入口热区 | \`x=W-108,\; w=96\` | 贴近右边缘，与签到镜像 |
| 共同纵向范围 | \`y=H-500,\; h=100\` | 底部在主按钮顶部 \`H-375\` 上方预留约25逻辑像素 |
| 图形本体 | 约64–72逻辑像素 | 下方附「签到」「背包」两字，文字不得被剪裁 |
| 点击热区 | 不小于88×88逻辑像素 | 720→360缩放时约44×44屏幕像素；以实际 DPR/缩放校验 |
| 主按钮 | 复用现有 \`x=112,y=H-375,w=496,h=88\` | 不改变原有主按钮位置与优先层级 |

**适配策略**：布局相对于屏幕安全区和主按钮锚点计算；横屏与短屏需动态压缩空白、不压缩热区；图标不能覆盖「第X关」、设置、图谱、教学、版本号，也不能拦截玉盘或首页展示区域的触控。实际定位以 360×640、375×667、390×844、430×932、横屏等截图微调。

### 2.3 入口交互

- 签到：点击打开签到面板；**当日可领取且尚未领取**显示小红点；领取成功后消失。不要以红点显示「连续天数」。
- 背包：点击打开背包面板；刚获得道具时可短暂高亮/角标提示，已查看后清除；默认不常驻显示总数量，防止误认为单一道具。
- 两个入口的图标与文字采用同一组件体系，大小、边框、触控反馈一致。
- 首次进入仍自动开始教学，不先弹签到；教学结束回首页后可见可领取标记。
- 关闭面板返回原首页原位置，不自动开始下一关；面板打开时禁止点击底层快捷入口或主按钮。

素材与字体对照：

### 3.2 两个首页图标的设计

**签到图标**：古风「日历花笺/小签牌」语义；可用简洁线绘日历页、角落一瓣桃花、日常勾记。采用与 \`src/ui.ts\` 现有 \`icon()\` 近似的线宽及豆沙色，底座为淡藕粉轻边框。**不要用亮黄金币宝箱、荧光日历、厚金属牌。**

**背包图标**：古风「锦囊/小玉匣」语义；采用简洁的布囊收口、系绳或半开玉匣轮廓，少量纹样点睛。默认与签到同一配色与描边。**不要用现代登山背包形状、3D 塑料箱或大面积翠绿宝石按钮。**

制作方法：先基于仓库当前首页实际截图做同屏比对；优先扩展现有 \`Icon\` 枚举与 \`icon()\` 线绘路径。若线绘不够表现，再产出透明 PNG/WebP 并统一素材尺寸、透明边界、边缘抗锯齿与资源体积。不得通过外链热加载游戏正式图标。

### 3.3 签到面板设计

- 名称优先「每日签到」，标题可用小字「七日有礼」作为副题；主弹窗沿用当前 \`modal()\` 的遮罩 \`rgba(81,57,69,0.28)\`、暖白底、细粉边框、宋体标题与中央花纹分割线。
- 7个奖励格采用「淡藕粉小花笺」风格；推荐前4后3的两行自适应排布；第7格可略强调，但不做跳脱主题的大金色礼盒。
- 已领：小勾/「已领」字样、适度降低对比度；今日待领：豆沙红边框与微弱花瓣高亮；未到：低对比度静态态，**不显示令人误以为连续签到惩罚的锁链**。
- 底部主按钮：「领取今日奖励」；领取后显示「今日已领取」并禁用；关闭按钮与旧弹窗一致。
- 可通过点击格子查看该天奖励说明，不能提前领取未来日期。
- 奖励动画：约0.5–0.8秒轻高亮/飞向右侧背包方向的视觉指引；兼容「减少动态效果」设置，减弱/关闭动画但**仍发奖**。避免粒子遮挡文字，避免多次点击产生重复发奖。

### 3.4 背包面板设计

- 标题：「我的背包」；同一模态弹窗规范与暖白底，统一关闭按钮。
- V1只显示两张道具卡，无需分页、分类 Tab 或空洞的9宫格。
- 提示：沿用关内的提示道具语义与图标；说明「指引正确的旋转方向」；显示库存数 \`×N\`。
- 消除：沿用关内消除图标；说明「选择并消除一只仍存在的玉镯」；显示库存数 \`×N\`。
- 数量为0时保留卡片与「暂无」态；**不要提供无效的「使用」按钮**，统一在正式关内使用。
- 获得道具后可从背包查看最新数量；面板与主页 UI 重新进入应保持一致。
- 弹窗高度按内容计算，底部关闭按钮始终可见；横屏、窄屏不挤压到屏幕外。

### 3.5 交互与可读性检查

使用既有 Button 按下蒙层，**不可**对按钮皮肤节点整体施加会导致消失的缩放/缓存改写；使用 \`cacheAs='none'\` 管理动态弹窗。文本和角标最低尺寸在实际手机上可辨认；触控目标遵循不小于44px 屏幕尺寸；打开遮罩不得透传点击。按钮音效沿用已有 \`Audio.play('button')\`；领取可在现有轻提示音与翠绿对齐亮光基础上做很轻的反馈，不能把背景配色改成荧光绿。

## 4. 七日累计签到系统

### 4.1 核心规则

| 事项 | V1.0规则 |
| --- | --- |
| 签到周期 | 7天为一轮；第7天领完后，**下一个自然日**从新一轮第1天开始 |
| 签到类型 | **累计签到，不要求连续** |
| 每日上限 | 每个有效账号/存档作用域、每个自然日最多成功领取1次 |
| 漏签 | 不清零、不倒退、不补签；下次来继续下一格 |
| 重置时间 | 北京时间（UTC+8）每天00:00 |
| 领取动作 | 主动点「领取今日奖励」才发奖 |
| 过期 | 本日未领取则当天不补，累计序号不前进 |
| 奖励位置 | 成功发奖直接进入**永久背包**，关卡重开不清零 |
| 教学用户 | 不阻断首次教学；返回首页后可主动领取 |
| 提示 | 如已领取，仍可打开面板看进度，领取按钮为禁用态 |

自然日键建议使用 \`YYYY-MM-DD\`（UTC+8）存储；禁止使用简单的 \`now - lastClaim >= 24h\`，否则与「每日0点刷新」冲突。首次新档从第1天开始。若玩家在第7天当天已签完，该日不能再重开第1天。

### 4.2 每轮奖励明细（确定数值）

| 累计天数 | 提示 | 消除 | 显示 |
| --- | ---: | ---: | --- |
| 第1天 | 1 | 0 | 提示 ×1 |
| 第2天 | 1 | 0 | 提示 ×1 |
| 第3天 | 0 | 1 | 消除 ×1 |
| 第4天 | 1 | 0 | 提示 ×1 |
| 第5天 | 2 | 0 | 提示 ×2 |
| 第6天 | 1 | 0 | 提示 ×1 |
| 第7天 | 1 | 1 | 提示 ×1、消除 ×1 |
| **单轮合计** | **7** | **2** | 共9件道具 |

补充：在高难关卡出现更多时，可通过**配置表**调整下一活动版本的奖励；一轮已经展示/领取的奖励，不能悄悄按新的配置回溯重算，建议保存奖励配置版本。

### 4.3 签到状态机

\`\`\`text
首页进入 → 查询已绑定账号/本地存档的签到状态
       ├─ 今日未领：显示红点 → 打开签到面板 → 点击领取
       │                                ├─ 成功：签到日推进、道具入背包、刷新红点与余额、请求云同步
       │                                ├─ 重复：提示今日已领，不二次发奖
       │                                └─ 异常：保留可重试状态，不先播放成功动效
       └─ 今日已领：无红点 → 仍可打开面板查看本轮进度
\`\`\`

关闭未领取的签到面板不自动发奖。登录/云档恢复进行中优先等账号作用域确定后显示可领取态；若平台不可用，按本地独立存档领取，但提示尚未同步，后续按可验证的同账号合并规则处理，绝不可将别的账号库存直接转入。

### 4.4 防重复领取要求与现实边界

- 在一次客户端运行中：点击锁定/请求去重；\`dateKey\`唯一，**签到状态更新与背包发奖在同一持久化事务中完成**，不可出现「红点消失但没到账」。
- 本地重进/多次点击：同一\`dateKey\`不可重复增库存；日志唯一键应包含账号作用域+日期，而不依赖按钮动画。
- 双设备/离线冲突：当前 TapTap H5 主要依赖**客户端云档**，并无真正的服务端签到交易接口；不能宣称「严格防作弊或跨设备同时领取的原子性已实现」。MVP必须用领取事件ID合并去重、旧存档不得恢复已消耗道具，并明确网络故障状态。
- 如产品后续要求**强一致、防刷签和独立账号权威库存**，必须增加具备认证、可信服务端时间、原子领取和库存扣减的服务端接口。这是增强阶段的依赖，不应以客户端计时伪装已实现。

## 5. 背包与道具规则

### 5.1 V1道具表

| 道具ID | 名称 | 来源 | 功能 | 是否可累积 | 失效期 |
| --- | --- | --- | --- | --- | --- |
| \`hint\` | 提示 | 7日签到（永久）；原有关卡免费/广告/分享（临时） | 显示一个当前有效的转镯方向/目标 | 背包部分可累积 | 背包永久 |
| \`erase\` | 消除 | 7日签到（永久）；原有关卡广告/分享（临时） | 玩家选中后确认消除一只有效手镯 | 背包部分可累积 | 背包永久 |

背包库存**独立于关卡**；不因为关卡更换、重开、通关、退出、升级版本而重置。奖励道具不折算金币，不计入旋转次数。仅正式关使用背包提示与消除；教学关仍走现有引导流程（默认不消耗永久道具）。

### 5.2 现有机制（代码实况）

目前 \`src/main.ts\` 正式关加载默认 \`hintLeft=1\`、\`eraseLeft=0\`。\`src/storage.ts\` 用 \`rewards[level][source]\` 管理广告/分享临时奖励，重开时调用 \`resetRewards(level)\`。这与「永久背包」不同，必须保留两个独立维度，不可把签到数量写进 \`hintLeft/eraseLeft\` 或现有 \`Reward.remaining\`。

### 5.3 关内消耗顺序（产品确定规则）

**提示**：
1. 优先使用本关免费提示（当前默认1次）；
2. 免费次数为0时，优先使用背包提示库存；
3. 背包不足时，使用本关**已经领取但尚未消耗**的广告/分享临时提示；
4. 全部为0，才弹出现有「看视频/分享获取」弹窗（按既有限制）；
5. 若广告/分享已领取完且库存为0，展示不可再获取提示，不产生负数。

**消除**：
1. 当前免费消除默认为0；
2. 优先使用背包消除库存；
3. 背包不足时，使用本关已领取的广告/分享临时消除；
4. 全部为0，再弹出广告/分享激励入口。

按钮显示：正式关仍用原有「提示 ×N」「消除 ×N」两颗按钮；**N = 本关免费剩余 + 背包库存 + 本关有效临时奖励剩余**。不要在关内再加一个常驻背包按钮，不得让两份余额重复相加或点击一次扣两处。

这一优先级沿用前期已确认的「免费次数 → 背包 → 激励」思路。需要注意：已领但未用的关卡临时奖励也应计入N，消耗时位于背包之后。若后续从数据发现玩家误浪费临时次数，可通过后续版本重新评审消耗顺序，不能在本版擅自改动。

### 5.4 成功扣减时机

- 提示：生成并准备展示**真实可执行**的下一步提示时才扣1个；无有效提示、加载失败、撤回、场景被打断时不扣。Debug 自动代转不扣道具。
- 消除：选中合法的仍存在手镯，确认且 \`removeWithTool\` 实际成功返回消除结果后扣1个；取消/错误目标/盘面忙/无结果均不扣。
- 使用过程必须做防重复点击/状态锁，直到模型操作结果与库存记录一致。奖励到账及消耗应触发轻量反馈与必要同步请求。
- 当局内有免费余量时优先消耗该余量；背包消费记持久流水，重复渲染、切场景不能重扣。
- Debug：原有 \`?debug=1\` 提示、消除无限使用、不减本关次数和背包、不参与正常道具测试统计；不可通过 Debug 提交排行作弊成绩。

### 5.5 重开/退出/存档继承

| 操作 | 本关免费次数 | 本关广告/分享临时奖励 | **背包永久库存** | 签到进度 |
| --- | --- | --- | --- | --- |
| 正式关重开 | 提示恢复1；消除0 | 沿用原规则：重置领取资格与临时余额 | **不变** | **不变** |
| 中途回首页/继续 | 继续当前余量 | 继续当前余量 | **不变** | **不变** |
| 完成/切换关卡 | 新关按默认次数 | 按新关规则 | **不变** | **不变** |
| 退出重进 | 从存档恢复 | 从存档恢复 | **从账号背包恢复** | **从账号签到状态恢复** |
| 云档失败 | 局内可用本地值 | 本地有效记录继续 | 保留本地账本，标记待同步 | 保留本地状态，标记待同步 |

## 6. 数据结构、存档兼容与同步方案

### 6.1 推荐领域模型（示意）

\`\`\`ts
type ToolKind = 'hint' | 'erase';
type LedgerAction = 'grant' | 'spend';

interface SignInClaim {
  claimId: string;                 // accountScope + UTC+8 dateKey 唯一
  dateKey: string;                 // YYYY-MM-DD
  cycleNo: number;                // 第几轮
  dayInCycle: 1 | 2 | 3 | 4 | 5 | 6 | 7;
  rewardConfigVersion: number;    // 防止后续调整奖表影响旧领取
  granted: Partial<Record<ToolKind, number>>;
  createdAtMs: number;
}

interface InventoryEvent {
  eventId: string;                 // 独一事件，重复合并不重复计量
  action: LedgerAction;
  kind: ToolKind;
  quantity: number;               // 正整数
  source: 'daily_signin' | 'level_tool';
  claimId?: string;               // 发奖事件绑定签到
  levelIndex?: number;            // 使用时的关卡ID
  createdAtMs: number;
}

interface SignInInventoryState {
  schemaVersion: 1;
  claims: Record<string, SignInClaim>;         // key = dateKey
  ledger: Record<string, InventoryEvent>;      // key = eventId
  // balance从有效账本计算/校验，不能把max(balance)当合并规则
}
\`\`\`

**推荐原则**：
- **永久背包账本独立于关卡奖励 \`meta.rewards\`**；关卡的 \`Reward\` 仍保存「video/share+代次+剩余」。
- 入账事件与 \`SignInClaim\` 用稳定 \`claimId\` 一起存储；每次查询先校验再读取。
- \`quantity\` 必须为安全范围内正整数；余额不能为负，也不能超出设定保护上限；若多端消费冲突产生债务，禁止把负数显示成有效库存或凭空补发，需有冲突校验/修复策略。
- 禁止用 \`Math.max(localCount, cloudCount)\` 合并永久库存；它会恢复已经消耗的道具。
- 不直接修改旧关卡临时奖励字段来表达永久库存，也不在领取时增加本关免费提示。

### 6.2 对现有存档的迁移要求

目前 \`CloudSave.version=1\`、\`Progress.version=2\`；\`validateCloud\` / \`validateMeta\` 具有严格结构校验。实现必须：
1. 增加可选的新功能域，或升级 \`CloudSave\` 结构版本并提供**v1→v2迁移**；旧存档读取后默认未签到、提示库存0、消除库存0，原有关卡/音效/排行榜/临时奖励全部保留。
2. 确保 \`validateMeta()\` 不再意外丢弃新字段，\`exportCloud()\`、\`mergeCloud()\`、\`bindAccount()\`、\`importGuest()\` 都显式支持签到与背包。
3. 若采用事件账本跨端合并，按唯一ID取并集并验证 claim/ledger 一致性；同一天冲突不得重复发奖；合法消费不能因落后云档恢复而“返还”。
4. 对「一个设备断网多次消耗、另一个设备仍读取旧档」进行幂等重放与冲突策略；只靠 TapTap 云档不是严格事务数据库，**强一致与防作弊仍需权威后端**。
5. 签到归属与账号作用域绑定：会话未识别/云档读取失败时不能加载其他账号背包；导入游客数据必须有明确操作和污染标记，避免直接影响排行榜。
6. 本地写入成功后先刷新界面，同时保留「待云同步」状态；上传遵守原有限频/重试策略，不新增签到即刻强制上传的并发风暴。

### 6.3 时间、离线与平台能力

- 签到日定义使用 UTC+8，严格以日期键判断；不依赖倒计时24小时。
- 有可验证平台/服务端时间时用可信时间；当前无权威时间 API 的场景，客户端时间只能作为便捷方案，**防改时钟能力有限**。检测明显倒退可提示联网校验，不能造成存档永久卡死。
- 断网可继续查看背包/既有库存。是否允许**离线领取新签到**应由产品与安全策略共同确认；本版建议在无权威服务端的 MVP 中支持同账号本地离线领取但标记待同步，并对跨端竞态做保守合并；若项目要求严格防刷，则需后端上线前改为联网领取。
- 广告/分享继续按既有平台能力判断；客户端不支持分享时必须给出「当前环境不可用」反馈，不把签到领取与系统分享能力绑定。

## 8. 操作流程与状态边界

### 8.1 正常签到

首启自动教学 → 回首页，左侧「签到」红点 → 打开「每日签到」→ 可查看本轮7日奖励 → 点击领取 → 幂等校验日期 → 领取记录与背包道具同事务保存 → UI 显示成功与飞入背包 → 首页左侧红点消失、右侧背包轻亮 → 原有云档同步排队 → 打开背包可见增加后的库存。

### 8.2 关卡内使用背包提示

关内点击「提示」→ 先判断是否可生成有效提示 → 生成后按「免费 → 背包 → 本关已领临时奖励」优先级扣一次 → 播放提示动作 → 刷新按钮总余量与背包库存 → 写本地进度/账本并按原策略同步。若没有有效可执行步骤，本次不扣。

### 8.3 关卡内使用背包消除

关内点击「消除」→ 进入选中模式 → 玩家点一只有效玉镯 → 二次确认 → 操作成功才依优先级扣1次 → 返回操作/刷新盘面；取消确认不扣。若库存和临时奖励均无，则走现有视频/分享获取弹窗。

### 8.4 重要边界

- 防止面板重复打开、遮罩下穿、触摸被盘面接管。
- 云存档账号切换需刷新首页展示、关闭旧账号遗留弹窗，避免奖励发错作用域。
- 正在播放广告/等待分享结果时不允许签到面板改变当前棋盘归属。
- 重开只重置原有**每关临时次数及领奖资格**，不能删背包、签到流水。
- Debug 模式任意次数使用不得污染永久账本；签到测试需另设测试存档/注入时钟，不能通过改真机系统时间刷真实奖励。
- 兼容失败后可恢复；**不能出现领取按钮显示成功但持久账本未写入**。

## 10. 开发建议顺序与交付物

1. **视觉基线验收**：截取当前首页、设置、关卡图谱/已有弹窗，形成签到和背包真实风格对照；确定左右图标在开始按钮**上方且贴屏幕两边**。
2. **数据层先行**：新增独立签到状态、库存事件与存档版本迁移；实现幂等领取、原子入账、云合并。
3. **UI 与交互**：加入两侧图标、签到弹窗和背包弹窗；复用 \`THEME\`、\`Button\`、\`panel\` 和字体；新字形补齐。
4. **关内联动**：统一显示/消耗优先级；确保 Debug、重开、退出与广告分享不破坏永久库存。
5. **自测与发布检查**：单元测试、构建、横竖屏实际操作、云档冲突测试、真实 H5 容器回归。后续如需提交代码与部署，另起实施任务。

### 10.1 不可妥协的完成标准

- 用户看到的是《转手镯消除》**原本美术风格的自然延伸**，不是新增一块风格割裂的游戏 UI。
- **左签到、右背包，靠两侧屏幕边缘，略高于开始按钮**；这是已确认的布局，而不是可自由调整到主按钮两边的建议。
- 签到奖励入背包；背包是永久库存；关卡免费与平台激励是临时来源；重开不能删除签到获得的道具。
- 老玩家升级不丢档、任何功能异常不制造道具、断网与账号冲突有明确可恢复路径。
- **本文只定义需求，不代表已实现上线。**
