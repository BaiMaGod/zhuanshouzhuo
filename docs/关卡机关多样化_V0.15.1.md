# 正式关卡机关多样化 V0.15.1（第一阶段）

日期：2026-10-18。开发分支：`feat/formal-mechanism-diversity-v015`。

## 根因与范围

V0.14 生成器将三色六角格中的一类单元选为中心，并将这些中心与所有相邻手镯相连，背景双端扣再将其余手镯成对连接。其后果是视觉上反复出现“一只镯一圈活动扣”的满邻域星形机关，玩家总是先对齐外围、再解除中心机关。

本阶段保留正式第1关、教学10关、原第45关和正式第2—10关的既有拓扑。重点重组正式第11—100关（第45关除外）共89关；保持每关从10镯起逐关增加一镯、六角密铺玉盘、两类固定方式、单缺口、吸附/阻挡物理规则不变。

## 五类局部结构

生成器在完全相同的老种子图上确定性选边，并保存成`src/formal-motifs.js`的离线掩码：
- `branch`：压缩大中心的扇出数，着重2—3扣分支。
- `focal`：允许少数重点大中心，周围换成小组。
- `weave`：保留更多共享接收镯与背景固定扣，侧重交织保持。
- `sparse`：减少满邻域星形，局部更多单扣/双扣和少量保持。
- `alternating`：组合不同中心度数与背景扣密度，避免全盘单一分布。

用`scripts/generate-formal-motifs.mjs`离线生成，游戏加载时仅根据保存的掩码选择预定锁杆，**没有设备端随机拓扑搜索或全盘求解器**。算法每次选边都要求连接图连通、每个非中心镯至少有一个活动扣、中心至少有一根活动杆、至少两组有效保持机关与共享接收镯；每只镯至多一根背景杆，避免单缺口永久死锁。

## 关卡多样性静态统计

统计对象：上述89关的固定种子与新选边结果。统计不是玩家实测难度，也不是完整物理通关结论。

| 维度 | 修改前 | 修改后 |
|---|---:|---:|
| 活动锁杆总数 | 9,890 | 6,767 |
| 背景双端杆总数 | 1,819 | 1,116 |

## 存档、提示与验证边界

89关定义修订号从`revision:1`升级为`revision:2`：旧关卡局内盘面必须重新开局，但玩家历史最佳成绩、星级、关卡解锁、已通教学及设置保留；广告/道具次数遵守重开逻辑。未改变的正式关仍保留修订号和原局内续局。

现有预置线性阶段提示图保持兼容，阶段扣号会随离线掩码重新编排，并且依然以即时真实扣位为准。**本阶段尚未增加两层中心之间的串联所有权**；真正跨层接力、残杆绕障特设谜题及通用分支DAG提示属于下一阶段，在物理碰撞/提示通关验证前不能承诺已经实现。

### 验收步骤

1. `npm run levels:motifs`后比较`src/formal-motifs.js`应保持一致。
2. `npm run test:fast`（初始几何、机关统计、按钮、进度与提示等）。
3. `npm test`：尤其是`tests/full/campaign-route.test.mjs`的100关连续碰撞合法完整解，不允许跳过失败关。
4. `tests/browser-input.mjs`：手机窗口真实手势通关、缩放、提示、局内重开、断点续局；至少抽测第11、13、20、45、70、100关。
5. 玩家试玩横向比较五类关卡的辨识度和疲劳程度，再考虑合入main/发布预览。

**状态**：开发分支已提交源代码与静态结构检查；尚未在当前受限执行环境完成全部Node/真实浏览器物理回归，因此不得将关卡视为已达到发布验收。
