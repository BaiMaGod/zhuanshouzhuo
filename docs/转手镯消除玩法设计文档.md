# 《转手镯消除》玩法设计文档

## 1. 游戏定位

游戏类型：旋转解锁 + 机关拆解 + 消除益智游戏。

核心体验：

- 观察手镯结构
- 寻找缺口方向
- 旋转手镯对准卡扣
- 解开连接关系
- 产生拆解反馈
- 完成连锁消除

目标：制作一款规则简单、反馈爽快、适合移动端休闲玩家的拆解类小游戏。

---

# 2. 核心玩法规则

## 2.1 手镯组成

每个手镯包含：

- 手镯主体
- 缺口（Gap）
- 连接卡扣（Connector）
- 旋转角度
- 当前连接状态

玩家通过旋转手镯，使缺口移动到卡扣位置。

---

# 3. 卡扣系统

## 3.1 固定卡扣

特点：

- 卡扣固定在世界位置
- 手镯旋转不会带动卡扣移动
- 需要玩家调整手镯缺口位置

示例：

```
手镯A
  |
 卡扣
  |
手镯B
```

---

## 3.2 跟随卡扣（绑定卡扣）

跟随卡扣固定安装在某一只手镯上，安装点相对这只手镯保持不变。所属手镯旋转时，卡扣绕该手镯圆心同步移动，卡扣朝向也同步旋转。

- 每个跟随卡扣必须明确所属手镯（owner）和被扣住的另一只手镯（receiver）。
- 卡扣位置由所属圆心、旋转角度、局部安装角和安装半径计算，不能当成固定世界坐标。
- 所属手镯的缺口和卡扣安装点一起转动，相对角度不变，不能靠转动所属手镯让自己的缺口“追上”自己的卡扣来解扣。
- 卡扣运动时，碰到任意其他未消除手镯的实体边缘，就阻挡所属手镯继续向该方向旋转。没有与这枚卡扣相连的手镯也会阻挡。
- 接触时停在接触位置，不允许穿模、瞬移或强制断扣；反方向仍可退回。
- 对方缺口是通道：先把对方缺口转到通行方向，再转所属手镯，让整个卡扣通过缺口并脱出。
- 对方缺口转到位本身不等于解除；卡扣仍在内孔时连接继续保留，必须真正脱出才解扣。
- 第三只手镯挡路时，可以先拆掉它，再继续旋转。
- 其他手镯旋转时，其实体也不能穿过当前停留的跟随卡扣。
- 解扣后，实体卡扣仍固定在所属手镯上，直到所属手镯消除。连接解除与卡扣实体消失是两种状态。

### 3.3 碰撞与输入

碰撞计算使用有厚度的卡扣与 C 型手镯实体，缺口两端圆角也算实体；不能只比较中心点或某个旋转角度。所属手镯自身不作为其卡扣的障碍物。

拖动、点击、左右微调、自动对准和整关演示共用旋转与碰撞判定。快速拖动要检查经过的路径，遇到障碍停在首次接触处。禁止自动按钮直接修改连接解除状态。

本原型银色表示固定卡扣，金色表示跟随卡扣，并标明所属手镯。受阻时突出挡路手镯，提示玩家转开缺口或先拆掉障碍。

# 4. 消除判定规则

## 4.1 单卡扣

固定卡扣：卡扣方向必须进入缺口的有效角度范围，扣除卡扣尺寸和手镯圆角占用后才可释放。视觉缺口与判定一致，不要求写死的角度。

跟随卡扣：用碰撞限制保证卡扣只从对方缺口通行；整个卡扣脱出对方实体边缘后，解除连接。

任一类型解除后，立即重新检查所有手镯的有效连接数量。零连接手镯自动掉落消除，无需再点击。最后一只也必须能消除。

## 4.2 多卡扣

一个手镯可能连接多个卡扣。

例如：

```
A
|
卡扣AB
|
B
|
卡扣BC
|
C
```

B 有两个连接：

- AB
- BC

必须满足：

```
AB解除
+
BC解除
```

B 才能消除。

# 5. 数据结构设计

## Bracelet

```ts
Bracelet {
 id:string;
 rotation:number;
 gapAngle:number;
 connectors:string[];
 removed:boolean;
}
```

## Connector

```ts
Connector {
 id:string;
 type:"fixed" | "follow";
 position?:{x:number,y:number}; // fixed 的世界位置
 ownerId?:string; // follow 的所属手镯
 localAngle?:number; // 相对于所属手镯的安装角
 orbitRadius?:number; // 安装点绕圆心的半径
 halfLength?:number; // 实体卡扣的碰撞形状
 pinRadius?:number;
 braceletA:string;
 braceletB:string;
 broken:boolean;
}
```

# 6. 游戏流程

```
进入关卡
 ↓
观察手镯连接关系
 ↓
旋转目标手镯
 ↓
缺口接近卡扣
 ↓
卡扣解除
 ↓
判断是否还有其它连接
 ↓
全部解除
 ↓
手镯消除
 ↓
进入下一层拆解
```

# 10. 开发原则

核心原则：

> 先保证真实拆解逻辑，再提升美术表现。

所有版本必须优先验证：

- 手镯能旋转
- 卡扣位置正确
- 缺口判定正确
- 消除反馈正确

# 11. HTML 试玩原型与验收

原型文件：`prototype/bracelet-play.html`。单文件，无需安装，浏览器打开即可。共 7 关，默认打开第 6 关，优先验证本次补充的跟随卡扣。

| 关卡 | 验证内容 |
| --- | --- |
| 1 | 单只手镯与固定卡扣 |
| 2 | 双镯连接，解除后两端更新 |
| 3 | 中间手镯多扣约束 |
| 4 | 四方连接 |
| 5 | 中心四扣 |
| 6 | 金扣随 A 转动，被 B 实体挡住；B 缺口让开后，A 带扣脱出 |
| 7 | 固定与跟随卡扣混合；C 镯会挡住金扣，先拆 C，再解除 B 银扣、转开 B 缺口、转 A 脱扣 |

第 6 关操作示例：旋转 A 可看到金扣被 B 挡住；把 B 缺口调到左下方（约 135°），再顺时针转 A。自动对准选中 A 时也会受阻；选中 B 时用于把缺口转到通行方向。整关演示先让出通道，再使用正常旋转脱扣。

本轮通过脚本检验：随镯位置变化、安装半径恒定、首次接触停止、快速旋转不穿越实体、受阻后反向退回、缺口通行、第三只手镯阻挡、反向实体碰撞、多扣约束、撤销、7 关完整拆解。

当前执行环境未安装可用浏览器，本轮尚未完成真实浏览器画面和手机触屏验收。不得把脚本测试通过描述为实机试玩通过。
