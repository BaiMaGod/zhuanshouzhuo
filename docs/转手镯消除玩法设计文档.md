# 《转手镯消除》玩法设计文档

## 1. 游戏定位

游戏类型：旋转解锁 + 机关拆解 + 消除益智游戏。

核心体验：

- 观察手镯结构
- 寻找缺口方向
- 旋转手镯对准卡扣
- 解开连接关系
- 产生拆解反馈
- 完成连锁消除

目标：制作一款规则简单、反馈爽快、适合移动端休闲玩家的拆解类小游戏。

---

# 2. 核心玩法规则

## 2.1 手镯组成

每个手镯包含：

- 手镯主体
- 缺口（Gap）
- 连接卡扣（Connector）
- 旋转角度
- 当前连接状态

玩家通过旋转手镯，使缺口移动到卡扣位置。

---

# 3. 卡扣系统

## 3.1 固定卡扣

特点：

- 卡扣固定在世界位置
- 手镯旋转不会带动卡扣移动
- 需要玩家调整手镯缺口位置

示例：

```
手镯A
  |
 卡扣
  |
手镯B
```

---

## 3.2 跟随卡扣（绑定卡扣）

跟随卡扣安装在所属手镯上，随该手镯旋转。连接必须建立在两只手镯边缘之间的实际扣位，卡扣不能悬在对方内孔深处。

- 每枚卡扣明确所属手镯（owner）和被扣住的手镯（receiver）。
- 图中的金扣横跨两镯之间的间隔，根部固定在所属镯边，另一端接触接收镯的实际边缘扣位。
- 卡扣已扣住接收镯时，所属镯朝实体强行转动会被约束。接收镯仍可转动，把细缺口对准这个实际扣位，解除连接。
- 接收镯的缺口与卡扣接触点重合才解扣；单纯朝向内孔中的一个虚构点不能解扣。
- 卡扣与所属镯的缺口相对位置不变，解扣使用接收镯的缺口。
- 连接解除后，卡扣仍固定在所属镯上。如果所属镯还有其他连接而保留，转它时能看到卡扣绕圆心移动。
- 移动卡扣碰到其他未消除手镯的实体边缘，停在首次接触处；这时可以反向退回。未与卡扣相连的镯子也会挡路。
- 可以先拆掉挡路手镯，再继续转动。
- 连接解除、卡扣实体消失、手镯消除分别管理。每只镯子所有连接解除后自动消除。

### 3.3 常规缺口尺寸与对准规则

常规手镯只开一条细缺口，缺口与卡扣宽度相近，保留很少的装配间隙。核心动作是旋转手镯，使细缺口与卡扣重合后解扣。

本 HTML 原型的逻辑尺寸：手镯截面宽 19，卡扣横向宽 7，缺口在内缘最窄处宽 8，间隙为 1。手镯缺口两侧使用平直切面，界面的金色小点放在环外，避免把缺口遮住。不同半径按同一缺口宽度换算角度。

对准容差由缺口宽度减去卡扣宽度计算，约为 0.5°；偏离 1° 或 3° 都不能解扣。提供 1° 微调、快速拖动途中检测和自动对准，方便玩家找准位置。

固定卡扣：保持世界位置不变，转动手镯，让细缺口对准卡扣。
跟随卡扣：随所属手镯转动，被实体阻挡；在与接收手镯的接触位置，让接收手镯的细缺口与卡扣重合后解扣。

### 3.4 碰撞与输入

碰撞使用有厚度的卡扣、环形实体和细缺口切面，图形与判定共用尺寸。所属手镯自身不作为绑定卡扣的障碍。

拖动、点击、左右微调、自动对准与整关演示共用旋转、碰撞和解扣判定。检查快速拖动经过的路径，遇到障碍停在首次接触处。自动按钮通过正常旋转解扣。

本原型银色表示固定扣，金色表示跟随扣并标注所属手镯。受阻时突出挡路手镯，提示转动细缺口或先拆障碍。

宽缺口、让整枚卡扣沿缺口旋转通过的思路，可留作特殊关卡变体，使用独立尺寸和规则；常规 MVP 使用本节的细缺口重合规则。

### 3.5 布局有效性

本 MVP 为同一平面的固定圆心布局，手镯实体互不重叠。任何两镯的圆心距离必须至少为两者外半径之和，再留少量间隔；不能靠遮挡顺序把交叉的实体伪装成有效连接。

- 手镯外半径为中心线半径加截面半宽。本原型截面半宽为 9.5。
- 所有关卡启动前校验两两间距，拒绝实体重叠。
- 跟随扣启动前校验接收镯的扣位确实落在卡扣实体上，拒绝卡扣悬空。
- 扣位位于接收镯的实际圆周，按这个扣位计算缺口角度，而不是按内孔中的卡扣中心计算。
- 第 6 关两只手镯中心距为 158，中心线半径均为 65，外径为 149，实体之间留 9 的间隔。
- 卡扣在边缘上的正常扣合与任意两只手镯实体相交必须分别处理。接收镯可绕固定圆心转动，把缺口转到实际扣位。
- 通关测试必须包含手镯几何布局和真实扣位检查，不能只验证角度和连接数量。

# 4. 消除判定规则

## 4.1 单卡扣

固定卡扣：缺口方向进入按实际宽度计算的细小容差范围，解除连接。

跟随卡扣：必须已接触被扣住手镯的实体边缘；该手镯的细缺口与卡扣接触点重合，解除连接。

解除后立即重新检查所有手镯。零连接手镯自动掉落消除，无需再点击，最后一只也必须能正常消除。

## 4.2 多卡扣

一个手镯可能连接多个卡扣。

例如：

```
A
|
卡扣AB
|
B
|
卡扣BC
|
C
```

B 有两个连接：

- AB
- BC

必须满足：

```
AB解除
+
BC解除
```

B 才能消除。

# 5. 数据结构设计

## Bracelet

```ts
Bracelet {
 id:string;
 rotation:number;
 gapAngle:number;
 gapWidth:number; // 缺口最窄处宽度，原型为 8
 gapHalf:number; // 由内缘半径和宽度换算半角
 connectors:string[];
 removed:boolean;
}
```

## Connector

```ts
Connector {
 id:string;
 type:"fixed" | "follow";
 position?:{x:number,y:number}; // fixed 的世界位置
 ownerId?:string; // follow 的所属手镯
 localAngle?:number; // 相对于所属手镯的安装角
 orbitRadius?:number; // 安装点绕圆心的半径
 halfLength?:number; // 实体卡扣的碰撞形状
 pinRadius?:number;
 docked?:boolean; // 是否占据实际扣位
 socketAngle?:number; // 接收镯实际扣位方向
 seatRotation?:number; // 所属镯扣合时的角度
 braceletA:string;
 braceletB:string;
 broken:boolean;
}
```

原型文件：`prototype/bracelet-play.html`。单文件，浏览器打开即可。共 12 关，默认第 8 关。保留已确认的前 7 关几何与解扣规则，新增 6–16 镯关卡。

| 关卡 | 验证内容 |
| --- | --- |
| 1 | 单镯细缺口对准固定扣 |
| 2 | 双镯固定连接，两端同步更新 |
| 3 | 中间手镯多扣约束 |
| 4 | 四方连接 |
| 5 | 中心四扣 |

| 7 | 先解开 B 的金扣，B 消除而 A 保留；顺时针转 A 可看到绑定金扣被 C 挡住，拆 C 后再解开 A 的银扣 |

| 11 | 12 只手镯、17 个固定扣，3 × 4 网格 |
| 12 | 16 只手镯、24 个固定扣，4 × 4 网格 |

第 6 关：选中绿色 B，顺时针转约 90°，使原本朝下的细缺口转到左侧扣位（世界方向 180°）。也可以选 B 后点“自动对准一扣”。卡扣已扣住 B 时，强行转 A 会受约束。

第 7 关：B 解扣后，A 因左侧银扣保留。顺时针转 A 时，已经解除连接的金扣仍随 A 转动并被 C 实体挡住。C 缺口转到下方银扣可拆 C；A 缺口转到左侧银扣可拆 A。三只手镯始终互不重叠。

本轮脚本通过：全部关卡实体间距校验、扣位在接收镯圆周且接触卡扣、旧重叠布局拒绝、卡扣悬空布局拒绝、绿色 B 的真实指针事件对准与清空、绑定金扣脱扣后移动、第三只手镯阻挡与反向退回、多扣约束、细缺口容差、撤销及 12 关清空。新增关卡还检查了棋盘边界、选中轮廓与底部说明间距、有限旋转角、有效颜色、密集关卡真实指针选中与拖转。

本轮另核对了新增密集关卡和跟随金扣关卡的静态 SVG 布局。小半径手镯的字母、剩余扣数与中心点击区随尺寸调整，8–16 镯仍沿用 8 像素缺口、7 像素卡扣及同一碰撞路径。当前环境无可用浏览器，真实浏览器与手机触屏尚未完成验收，静态渲染与脚本检查不等于实机试玩。
