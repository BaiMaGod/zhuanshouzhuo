## 2. 游戏定位与基本操作

类型：旋转解锁、机关拆解、消除益智。

目标：观察连接关系，合法旋转手镯，使当前有效扣合连接全部解除，最终消除所有手镯。

MVP 使用固定圆心二维布局。手镯绕自身圆心顺、逆时针旋转，缺口随环体旋转；不能平移圆心、掰大缺口或直接拖动锁杆。正式输入为拖动环体，点击仅用于选中；界面不提供旋转、微调、撤销或演示按钮。已有内部辅助入口只用于开发验证，吸附与内部验证必须走同一合法路径。

缺口保持细开口，其净宽与需要通过的扣体宽度接近且实际能够容纳，不靠放大缺口绕过连接关系。难度来自观察、连接依赖、保持对齐组合与操作顺序，不靠极小点准容差或输入故障。

## 3. 两类锁杆

### 3.1 手镯固定式

一端的实心固定座固接于所属手镯 owner；杆身及另一端空心活动扣组成完整刚性件，活动扣扣住另一只接收手镯 receiver。

- 固定座与杆件相对 owner 的安装位置、方向不变。
- owner 可以合法旋转时，固定座、杆身和活动扣整体随 owner 旋转。
- receiver 旋转不直接带动这根锁杆；其环体可在允许的套扣关系中相对活动扣滑动。
- 使用 receiver 的缺口对准该活动扣，不能拿 owner 的缺口替代。
- owner 旋转会改变活动端的世界位置，必须重新判断接触、扣合、碰撞与其他相关连接；不能只更新 owner 的缺口。
- owner 消除时，其完整锁杆随之消除。
- receiver 消除但 owner 尚在时，连接失效，完整锁杆仍属于 owner；随后 owner 合法旋转时，它仍随 owner 转动。

固定在手镯上不等于固定在背景上。“固接”描述局部安装关系，不代表所有世界坐标永远不动。

### 3.2 背景固定式

锁杆固定在背景上，通常两端都是空心扣，分别扣住两个手镯 A、B。

- 整根锁杆的位置、朝向、长度及端点形状保持固定。
- A、B 旋转均不带动锁杆。
- 每个空心扣由其所扣手镯的缺口独立判断对齐。
- A 端对齐不代表 B 端也解除；两端状态分别管理。
- 某端手镯消除后，该端连接失效，不能重新扣住已不存在的手镯。
- 不能强行给这类锁杆指定某个手镯 owner，套用“随 owner 消除”的规则。

背景固定式锁杆本体何时移除尚未被明确确认。实现时可保留背景实体，不得在一端消除时擅自删除整杆；正式确定其移除时机前，标注为待确认。关卡完成按全部手镯消除判断，不能要求背景杆必须消失才通关。

### 3.3 对照表

| 项目 | 手镯固定式 | 背景固定式 |
| --- | --- | --- |
| 锚定对象 | 所属手镯 owner | 背景 |
| 常见结构 | 实心固定座 + 杆身 + 空心活动扣 | 空心扣 + 杆身 + 空心扣 |
| 世界姿态来源 | owner 当前姿态与局部安装参数 | 固定背景姿态 |
| 接收手镯旋转 | 不直接带动杆件 | 不带动杆件 |
| 锁杆消除 | 随 owner 消除 | 尚待确认，不套用 owner 规则 |

两类结构必须在视觉上可辨认，不能仅用颜色区分。背景锚定属于本版明确允许的结构，不再写成“普通关卡不得有世界锚点”。

## 4. 完整实体与连接状态

分别管理锁杆本体、每个活动端的当前连接状态、手镯生命周期。

活动端状态：
- 扣合：相关实体存在且活动端仍扣住环体。
- 当前对齐／暂时脱扣：合法到达缺口、满足真实通行关系，暂时不提供扣合约束。
- 失效：目标手镯已消除，或手镯固定式所属杆已随 owner 消除，不再提供连接约束。

暂时脱扣不能永久累计。相关手镯与锁杆尚在时，缺口与扣体的相对位置离开有效对齐范围，该端重新扣合。重新扣合按尚存活动扣与接收镯的实际关系判断，不能将缺口对齐解释为 owner 已获得自由转动能力。

“当前对齐／暂时脱扣”是用于判断当前扣合与消除条件的状态，不表示扣体已经离开接收镯，也不自动解除环体对整根锁杆运动的实体限制。本版不增加“对齐后 owner 转动，把扣体从缺口带离”的玩法；此前审查中的该例子未经几何验证，撤回，不作为开发依据。

解扣状态变化本身不移动、折放、收回、伸缩或隐藏锁杆部件。手镯固定式随 owner 的正常旋转，与擅自为脱扣动画改变安装姿态是两回事。

相邻手镯消除不能误删尚存 owner 的杆件，不能只剩固定座或半截扣。背景固定式一端目标消除也不能误删另一端有效连接。

## 5. 旋转、碰撞与合法脱扣

### 5.1 可转性

“锁杆随 owner 旋转”是正确运动规则，不意味着 owner 在任何扣合状态下都能任意转动。

每次请求必须判断：
1. 手镯是否 active，是否被相关消除演出占用。
2. 固接于该镯的所有杆件随旋转后的姿态。
3. 所有扣合端能否维持允许的接触与相对滑动。
4. 环体、固定座、杆身、活动扣是否碰到其他实体。
5. 途中对齐、重新扣合、连接失效是否改变后续约束。

不能把“有固定端”直接写成所有结构下一律不可转，也不能默认所有镯都可自由转。活动扣仍套在另一镯的环体上时，所属镯的旋转带动整根杆件绕所属镯圆心运动，必须受到该环体与其他实体约束；不能仅因连接状态变为 aligned 就取消这些碰撞。

例：A 的缺口对齐 B 所属活动扣。扣体仍处于 A 的扣位，B 转动时扣体绕 B 的圆心运动，并不必然沿 A 的细缺口通行。因此不能据此放行 B、自动把扣体移出 A，或永久删除连接。若所请求路径被 A 环体卡住，B 必须停住。只有通过实际结构验证的路径才允许执行。

“锁杆随 owner 旋转”描述允许旋转时的运动方式，不是可转许可。owner 的活动扣目标镯已消除后，这条扣合失效；完整残留杆仍随 owner 合法旋转并参与其他实体碰撞。目标镯尚在时，不预设所谓转出路径或额外局部活动能力。

碰到首次真实阻挡即停，不穿透、不自动换路。合法反向退回应可用。合法套扣接触与实际实体阻挡分开判断，不全局豁免某个 receiver 的所有碰撞。

### 5.2 对齐判定

必须满足：
- 使用被该活动端扣住的手镯缺口。
- 扣体位于真实环体扣位，不悬在内孔中。
- 实际接触方向与缺口对应，净开口能够容纳需通过的部分。
- 脱扣所需通行关系没有实体阻挡。
- 经合法连续旋转到达，未瞬移或越障。

角度采用归一化世界角与环形最短角差，正确处理 359°／0°。缺口方向为 rotation + gapLocalAngle。扣位方向由当前锁杆姿态计算：手镯固定式加入 owner 姿态，背景固定式读取背景姿态。

可参考局部容差估算：
tolerance ≈ asin((gapClearWidth - movingEndWidth) / (2 × contactRadius))

估算不替代真实形状与通行校验。视觉和判定使用同一几何参数。辅助吸附范围与真实容差分开，吸附也不能越障。

### 5.3 连续路径

拖动、微调、自动对准、演示共用求解入口。快速拖动按路径处理碰撞和状态变化，不能只看终点，也不能把途中经过某扣位永久登记为解锁。

旋转 receiver 后更新对应端的扣合状态，不直接移动其所属杆件；owner 的旋转请求先经连续约束和碰撞验证，再按实际允许完成的角度更新固接杆姿态及相关状态。禁止先将 owner 转到目标角，再因扣体已经离开原位而倒推为合法脱扣。

## 6. 消除与状态更新

手镯仍有任何有效扣合约束就不能消除，包括它作为接收镯被扣住，以及其所属杆仍通过扣合端连接其他镯的关系。

当前所有有效扣合连接均解除或失效时，手镯自动消除，不额外要求缺口朝向某个方向。

“同时满足”是当前状态同时成立，不要求玩家同时拖动多个镯；可以先对齐一只并保持，再调整另一只。若第一只转离尚存扣位，连接恢复，不能累计之前对齐。

推荐顺序：
1. 推进至下一个合法旋转事件。
2. 按类型更新锁杆世界姿态。
3. 更新相关端的对齐、重新扣合与失效状态。
4. 同一轮完成相关连接更新后检查手镯消除，避免中间状态误删。
5. 消除满足条件的手镯；只移除其拥有的手镯固定式完整杆件。
6. 指向已消除手镯的其他活动端失效，其尚存杆件完整保留。
7. 继续更新受影响约束，必要时触发后续合法消除。
8. 全部手镯消除后只结算一次。

最后一只没有有效扣合连接时自动消除，不留下残镯。背景杆的存在不单独阻止通关；但目标手镯尚在时，其有效扣合仍须解除。

## 7. 示例与教学

### 7.1 三镯顺序模板 B→A→C

L_AB 属于 A，活动扣扣住 B；L_CA 属于 C，活动扣扣住 A。

- 先合法转 B，对齐 L_AB 活动扣。若 B 无其他扣合连接，B 消除。
- L_AB 与 B 的连接失效，但完整杆件仍留在 A 上。
- A 可以合法旋转时，L_AB 随 A 旋转，残留杆件仍参与碰撞。
- 再合法转 A，用 A 的缺口对齐 L_CA；A、C 满足零有效扣合条件时消除。
- A、C 各自所属杆件随所属镯消除。

B→A→C 是待用真实几何验证的顺序模板，不虚构目标角，也不证明所有带固定端的镯开局一律不可转。布局必须保证残留杆件不会把后续合法路径挡死。

### 7.2 保持多镯对齐

G 拥有两根手镯固定式杆件，分别扣住 A、B。假设 A、B 可以合法操作，且还有其他连接而不会提前消除。

先让 A 对齐 G 的活动扣并保持，再让 B 对齐另一扣；G 当前所有有效扣合连接解除后消除，其两根杆件随 G 移除。若过程中 A 转离，G—A 重新扣合，G 不能提前消除。

### 7.3 背景双端杆

背景杆两端分别扣住 A、B。旋转 A 仅改变 A 端对齐状态，杆本体不动，B 端仍独立有效。A 消除后，A 端失效，B 端继续按 B 的缺口与固定扣位判断，不能一并永久解锁或删除整杆。

### 7.4 “逐个解开”的提示边界

可以按当前真实约束继续尝试调整其他扣位，不要求每次对齐都先消除手镯。但只有相关手镯或所属锁杆消除、使连接失效后，才不需要继续保持这条连接的对齐。若只是暂时对齐且相关实体仍在，转离就重新扣合，不能写成“逐个累计解开”。“逐个拆除”必须明确每一步实际消除的对象，不能暗示经过各扣位一次就能清空。

教学依次介绍两类锚定、缺口对齐、转离重新扣合、保持组合、消除归属和实体阻挡。正式教程不展示调试计算。

## 8. 数据模型与几何来源

锁杆独立保存，活动端各有权威状态，不在两个镯中重复累计解锁。

建议类型：
- Bracelet：圆心、半径、环宽、rotation、gapLocalAngle、gapClearWidth、life。
- RingMountedRod：kind = ringMounted；ownerId；相对 owner 的安装点与局部方向；固定杆长与实体形状；一个 receiver 活动端。
- BackgroundRod：kind = backgroundFixed；固定世界姿态；固定杆长与实体形状；通常两个活动端，各自包含 receiverId 与连接状态。
- ActiveEnd：目标镯、端点形状、通行尺寸及 latched／aligned／inactive 状态。

手镯固定式的世界安装点由 owner 圆心与旋转后的局部安装点计算，世界方向为 owner.rotation + 局部杆方向，活动端由安装点、世界方向与杆长计算。

背景固定式世界姿态不加入任何手镯 rotation。不能只用一个永久 fixedWorldPose 字段表示两类杆件，也不能把活动端位置直接绑定到 receiver.rotation。

连接状态是当前几何与生命周期的结果，不使用永久 unlocked 记录。撤销保存手镯姿态、活动端状态、生命周期、计数；先取消旧回调，再按锚定类型重建杆件姿态。

## 9. 关卡布局、难度与有解性

正式关卡必须按背景玉盘的内部可用轮廓生成与验收。所有手镯的完整外缘及阴影都要落在盘内，不能只检查圆心或矩形包围盒；边框、顶部和底部装饰不属于可用盘面。布局沿玉盘轮廓收拢，保持连续紧密排列，内部不留空格或人为拉开间距。若模板超出盘面，应保持真实镯径、相邻中心间距和锁扣几何，将整个密阵居中并统一适配到盘面内，不能单独挪动边缘镯破坏机关。

当前54镯正式模板在加载时使用实际玉盘宽高进行椭圆包含校验：安全半轴为图片宽度的45.5%、高度的40.5%，逐镯检查半径56世界单位的完整旋转外观包络（含阴影），选择满足边界的最大统一比例。适配完成后注册背景，后续缩放和平移共用同一变换；不同屏幕比例及完整合法通关路线均需回归。

V0.8.0 的54镯模板重新排布为10行（3、5、6、7、6、6、7、6、5、3），上下行宽对称，每行连续填满，行中心相对盘心的偏移不超过四分之一镯间距，避免长条、偏斜和边缘凹口。相邻格距仍为92.0001世界单位，保留62杆与9组双镯保持机关，并重新验证54次合法拖动的通关路线。

正式关顶部只保留一行按钮栏与一行无底框计数：左上方原图谱位置放首页和重开图标，中央显示“第xx关”（正式关独立从第1关编号），右上方为音效、玩法图标。所有顶部按钮只显示图标。按钮使用柔和玉色、细边缘与浅阴影，去掉多重金边和厚底座；关卡标题采用暖棕色#765634、43逻辑字号，左右计数采用#876d48。下一行左侧显示“xx 手镯待解”，右侧显示“xx 次转动”，不加背景框。取消正式关的图谱按钮和大标题背景框。

720逻辑宽度下玉盘从y=142开始，高度为舞台高度减244；底部只保留一行，左侧是提示按钮，中央为缩小、全盘、放大。提示与全盘同一行，首页和重开不再占据底部空间。盘面和操作区不得重叠。最底层使用接近玉盘的柔和纯色背景（暖米色#eee3ca），不绘制花园图片，保留现有玉盘素材，玉镯与空心扣保留原素材、完整形状和实体尺寸，不得用放大缺口或锁扣改变判定来换取可读性。

关卡数量按实际盘面容量与触控可读性确定，不将54作为未来关卡的固定容量；优先布局轮廓和连接质量，不能靠无限缩小环体堆积数量制造难度。当前54镯模板已通过几何与路线验证，因此这一轮保留数量。

紧密排列但环体不非法重叠，缺口、扣体、归属与背景锚定清晰。可用菱形、三角形、六角形、心形、弯月等轮廓，不能靠放大间距或遮挡连接规避机械关系。

加载检查：
- 参数有限，局部与世界坐标定义明确。
- 两类杆件锚定正确，安装点连续，不悬空。
- 活动端真实扣住目标环体。
- 初始无非法碰撞、隐性清场或错误零连接。
- 完整扣体可见，不只显示半截。
- 残留杆件在后续旋转中仍参与碰撞。
- 每关至少有遵守两类运动、重新扣合与消除的完整合法解。

生成先用已验证模板，再用同一规则正向求解。增加镯数、链条层数或倒推不自动保证有解。难度评估与有解验证分开，不把错误锁死、容差小或外圈连点当作高难谜题。

## 10. 辅助功能与界面

正式关提供首页、重开、音效开关、玩法说明、提示、全盘复位与缩放；教学关保留新手引导和扣位提示。旋转完全由手指拖动完成，不显示微调、代转、撤销或演示按钮。

点击正式关提示，在当前合法动作对应的手镯上显示与新手教程同款的手指动画及短弧方向箭头，标出目标扣位，不弹窗、不显示镯编号、不画选中圆圈。顺逆时针方向必须来自真实连续碰撞规则验证的动作。优先匹配完整验证路线及半途拖转进度；偏离路线时在独立Worker中查找当前合法的释放或对齐动作，局部提示不等于已证明后续整盘有解。提示只读玩家状态，不转动玉镯、不改变扣位、不增加转动次数。

手指与箭头随背景和玉镯的视角同步更新，并裁切在操作区域内；目标离屏时平移视角使其可见，保留当前缩放比例。实际拖转、重开、回到首页和切关清除旧提示。规划期间按钮显示“观察…”，找不到合法动作时显示“暂无路线”，不能将其解释为整关死锁。

自动功能必须使用正常旋转路径，不直接赋目标角、永久删除连接或强制清空。规划需要考虑重新扣合、owner 带动杆件、残留实体和保持对齐组合。局部规划找不到解不能直接宣称整关死锁。

正式界面的常驻文字只显示关卡编号、剩余手镯和转动次数，不显示手镯字母编号、选中编号或教学提示文字；手指方向提示仅在主动点击提示后出现。选中反馈通过现有玉石材质的相对亮度表达，不绘制圆圈线；受阻反馈由真实碰撞位置和音效表达。脱扣数量不是正式界面的必需项，不作为永久解锁进度条。开发模式可显示锁杆类型、owner 或背景锚定、端点目标、当前扣合状态与阻挡对象。

锁杆、固定座、活动扣完整绘制。高亮只能改变表现，不改变实体几何。手镯固定式的合法随动必须正确显示；背景杆保持原位。颜色之外需有结构辨识。

移动端用指针捕获；松手、取消、切后台、撤销、重开与切关解除拖动锁，取消旧动画事件。密集区域防止误选相邻镯。

## 11. 实施与验收

先验证双镯与两类杆件，再验证三镯、重新扣合、多镯组合、密集异形关。未通过规则与真实输入验证前不以扩充数量代替修正。

| 编号 | 场景 | 必须结果 |
| --- | --- | --- |
| R01 | 合法旋转手镯固定式 owner | 完整杆件随动，局部安装关系与长度不变 |
| R02 | 旋转 receiver | 不直接带动他镯所属杆件 |
| R03 | 旋转背景杆两端手镯 | 背景杆位置与方向不变 |
| R04 | 背景杆只对齐一端 | 另一端状态独立，不误解锁 |
| R05 | 对齐活动端后转离 | 尚存连接重新扣合，不累计 |
| R06 | owner 请求旋转，活动扣仍在另一镯上 | 连续验证环体约束，不因 aligned 状态放行或永久解锁 |
| R07 | 多连接只解除一条 | 尚有扣合时不消除 |
| R08 | 先后保持相关对齐 | 全部有效扣合解除才消除 |
| R09 | receiver 消除、owner 尚在 | 完整杆保留，之后随 owner 合法旋转 |
| R10 | owner 消除 | 只移除该 owner 的完整杆件 |
| R11 | 背景杆一端目标消除 | 该端失效，另一端及本体不被误删 |
| R12 | 最后一只无有效连接 | 自动清空，无额外点击 |
| R13 | 实体阻挡与反向退回 | 不穿透，允许合法退回 |
| R14 | 快速拖动与跨 0° | 连续状态正确，不漏事件 |
| R15 | 缺口尺寸或路径不满足 | 不脱扣，不靠扩大容差兜底 |
| R16 | 对齐与消除前后查看扣体 | 无半扣、折放、伸缩或误删 |
| R17 | 撤销、重开、切关 | 姿态与状态一致，旧回调无效 |
| R18 | 手动、微调、自动、演示 | 同一规则，无自动越障 |
| R19 | 手机输入与完整通关 | 无锁死、残镯或重复结算 |
| R20 | 整关与残留杆件 | 存在完整合法解，后续碰撞不被忽略 |
| R21 | A 对齐 B 所属扣，B 请求会撞 A 环体的旋转 | B 停住，扣体不自动转出，不移动或删除连接来放行 |
| R22 | 相同结构仅改变 latched／aligned 状态 | 对齐可改变消除条件，但不全局关闭环体实体碰撞 |
| R23 | 手镯固定式与背景固定式混合关 | 随动与固定各自正确，状态变化不串改另一类杆件 |

验收分别记录规则测试、实际绘制、手动完整试玩、自动完整试玩与手机输入。静态审查、模拟清空、截图都不能代替真实输入验收。

## 12. 待确认与后续范围

待确认的玩法条款：背景固定式锁杆本体的移除时机。不得凭手镯固定式归属规则自行决定。

实现验证事项：具体结构的接触、旋转范围、连续碰撞以及逻辑消除与动画移除的时序。这些需要完整技术规格与测试，不得以验证为由增加未经确认的“扣体转出”玩法，或改变两类锚定、重新扣合和消除规则。本文不宣称这些实现细节已全部验证完成。

核心稳定后扩展多连接、关卡、美术、音效、玉石材质、外观收藏与图鉴。成长以关卡、提示与外观为主；未明确的幸运值、自动拆解成长不纳入 MVP。限时、最少操作与排行放在基础稳定后，辅助与商业功能均不得越障、改尺寸或改变锁杆锚定。

仓库原型为 prototype/bracelet-play.html。本次仅修正文档；原型需另外按本文核对与修复，不把现有原型行为作为已通过依据。

## 正式关卡道具次数（V0.11.1）

- 100个正式关卡每次新挑战默认提供提示1次、消除1次；教程提示不限次数。
- 底部按钮显示“提示 ×1”“消除 ×1”，用尽显示 ×0 并置灰；点击显示本关道具已用完的轻提示。
- 提示成功找到有效动作并展示手指方向动画后才扣除；搜索失败、取消搜索、重复点击不扣次数。提示播放期间不重复购买或刷新提示。
- 消除先进入选取状态，再选择目标并确认；再次点击按钮或按 Escape 可取消选取，确认弹窗取消亦不扣次数。拖动或双指缩放不算选取目标。
- 只有成功消除后扣除1次；沿用现有消除规则和自然解扣结算，不移动其他手镯，不另改锁扣位置。
- 道具余量与当前盘面同步保存。刷新、退出、再从首页或图谱进入同关均继续原进度；每关独立保存，不跨关累积。
- 确认重开或通关后再次挑战，恢复初始盘面和各1次道具。新关默认各1次；已开始过的关卡继续其原存档。
- 暂不接入购买、广告补充或全局道具库存。旧版本没有局内存档时从各1次开始；无效局内存档回退到新挑战。
