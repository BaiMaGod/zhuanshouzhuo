# 《转手镯消除》玩法设计文档

## 1. 游戏定位

游戏类型：旋转解锁 + 机关拆解 + 消除益智游戏。

核心体验：

- 观察手镯结构
- 寻找缺口方向
- 旋转手镯对准卡扣
- 解开连接关系
- 产生拆解反馈
- 完成连锁消除

目标：制作一款规则简单、反馈爽快、适合移动端休闲玩家的拆解类小游戏。

---

# 2. 核心玩法规则

## 2.1 手镯组成

每个手镯包含：

- 手镯主体
- 缺口（Gap）
- 连接卡扣（Connector）
- 旋转角度
- 当前连接状态

玩家通过旋转手镯，使缺口移动到卡扣位置。

---

# 3. 卡扣系统

## 3.1 固定卡扣

特点：

- 卡扣固定在世界位置
- 手镯旋转不会带动卡扣移动
- 需要玩家调整手镯缺口位置

示例：

```
手镯A
  |
 卡扣
  |
手镯B
```

---

## 3.2 跟随卡扣（绑定卡扣）

跟随卡扣固定安装在某一只手镯上。所属手镯旋转时，卡扣绕该手镯圆心同步移动，安装点相对手镯保持不变。

- 每个卡扣明确所属手镯（owner）和被扣住的另一只手镯（receiver）。
- 卡扣世界位置由所属圆心、旋转角度、局部安装角和安装半径计算。
- 卡扣与所属手镯的缺口相对位置不变，解扣使用被扣住手镯的缺口。
- 卡扣碰到其他未消除手镯的实体边缘时，所属手镯停在首次接触位置；可以反向退回。
- 另一只手镯没有与该卡扣相连，也仍然可以挡路。
- 在接触位置，转动被扣住手镯，让它的细缺口刚好对准卡扣接触点。缺口和卡扣重合后，连接立即解除，播放脱扣演出。
- 也可以先把被扣住手镯的缺口转到预计接触位置，再转动所属手镯，直到金扣与缺口重合。
- 卡扣尚在另一只手镯内孔深处、没有接触边缘时，只是朝向缺口不能解扣。
- 若第三只手镯挡路，可以先拆掉它。
- 转动其他手镯时，其实体也不能穿过停留的跟随卡扣。
- 连接解除与实体消失分别管理；所属手镯尚未消除时，绑定卡扣仍跟随它。

### 3.3 常规缺口尺寸与对准规则

常规手镯只开一条细缺口，缺口与卡扣宽度相近，保留很少的装配间隙。核心动作是旋转手镯，使细缺口与卡扣重合后解扣。

本 HTML 原型的逻辑尺寸：手镯截面宽 19，卡扣横向宽 7，缺口在内缘最窄处宽 8，间隙为 1。手镯缺口两侧使用平直切面，界面的金色小点放在环外，避免把缺口遮住。不同半径按同一缺口宽度换算角度。

对准容差由缺口宽度减去卡扣宽度计算，约为 0.5°；偏离 1° 或 3° 都不能解扣。提供 1° 微调、快速拖动途中检测和自动对准，方便玩家找准位置。

固定卡扣：保持世界位置不变，转动手镯，让细缺口对准卡扣。
跟随卡扣：随所属手镯转动，被实体阻挡；在与接收手镯的接触位置，让接收手镯的细缺口与卡扣重合后解扣。

### 3.4 碰撞与输入

碰撞使用有厚度的卡扣、环形实体和细缺口切面，图形与判定共用尺寸。所属手镯自身不作为绑定卡扣的障碍。

拖动、点击、左右微调、自动对准与整关演示共用旋转、碰撞和解扣判定。检查快速拖动经过的路径，遇到障碍停在首次接触处。自动按钮通过正常旋转解扣。

本原型银色表示固定扣，金色表示跟随扣并标注所属手镯。受阻时突出挡路手镯，提示转动细缺口或先拆障碍。

宽缺口、让整枚卡扣沿缺口旋转通过的思路，可留作特殊关卡变体，使用独立尺寸和规则；常规 MVP 使用本节的细缺口重合规则。

# 4. 消除判定规则

## 4.1 单卡扣

固定卡扣：缺口方向进入按实际宽度计算的细小容差范围，解除连接。

跟随卡扣：必须已接触被扣住手镯的实体边缘；该手镯的细缺口与卡扣接触点重合，解除连接。

解除后立即重新检查所有手镯。零连接手镯自动掉落消除，无需再点击，最后一只也必须能正常消除。

## 4.2 多卡扣

一个手镯可能连接多个卡扣。

例如：

```
A
|
卡扣AB
|
B
|
卡扣BC
|
C
```

B 有两个连接：

- AB
- BC

必须满足：

```
AB解除
+
BC解除
```

B 才能消除。

# 5. 数据结构设计

## Bracelet

```ts
Bracelet {
 id:string;
 rotation:number;
 gapAngle:number;
 gapWidth:number; // 缺口最窄处宽度，原型为 8
 gapHalf:number; // 由内缘半径和宽度换算半角
 connectors:string[];
 removed:boolean;
}
```

## Connector

```ts
Connector {
 id:string;
 type:"fixed" | "follow";
 position?:{x:number,y:number}; // fixed 的世界位置
 ownerId?:string; // follow 的所属手镯
 localAngle?:number; // 相对于所属手镯的安装角
 orbitRadius?:number; // 安装点绕圆心的半径
 halfLength?:number; // 实体卡扣的碰撞形状
 pinRadius?:number;
 braceletA:string;
 braceletB:string;
 broken:boolean;
}
```

# 6. 游戏流程

```
进入关卡
 ↓
观察手镯连接关系
 ↓
旋转目标手镯
 ↓
缺口接近卡扣
 ↓
卡扣解除
 ↓
判断是否还有其它连接
 ↓
全部解除
 ↓
手镯消除
 ↓
进入下一层拆解
```

# 11. HTML 试玩原型与验收

原型文件：`prototype/bracelet-play.html`。单文件，无需安装，浏览器打开即可。共 7 关，默认第 6 关。

| 关卡 | 验证内容 |
| --- | --- |
| 1 | 单镯细缺口对准固定扣 |
| 2 | 双镯固定连接，两端同步更新 |
| 3 | 中间手镯多扣约束 |
| 4 | 四方连接 |
| 5 | 中心四扣 |
| 6 | 转 A 带动金扣，被 B 实体挡住；再转 B 的细缺口与接触处重合，即解扣 |
| 7 | 先拆挡路 C，解除 B 银扣；转 A 靠到 B，再转 B 细缺口对准金扣 |

第 6 关操作示例：选 A 旋转到受阻，随后选 B，点“自动对准一扣”验证细缺口与金扣重合。也可以拖动 B 或用 1° 微调手动完成。跟随卡扣对准位置随实际接触位置计算，不写死 135°。

脚本验收通过：缺口与卡扣宽度接近，偏离 1° / 3° 保持连接，细缺口对准后立即解扣，内孔深处朝向对齐不解扣，跟随卡扣移动，碰撞阻挡，快速拖动不穿模，第三只手镯阻挡，多扣约束，撤销，1° 微调及 7 关清空。

当前环境未安装可用浏览器，真实浏览器与手机触屏尚未完成验收。静态 SVG 检查与逻辑脚本不等于实机试玩。
