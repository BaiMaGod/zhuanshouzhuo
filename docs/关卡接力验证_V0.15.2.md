# 正式关卡二层接力与验证 V0.15.2

日期：2026-10-18；开发分支：`feat/formal-mechanism-diversity-v015`。

## 为什么增加这一层

V0.15.1 的五类离线掩码解决了“每个中心挂满一圈扣”的外观重复，但中心仍不能成为其他中心的下游。因此新增经过物理验证的**接收镯同时作为活动锁杆 owner**结构：A 的活动扣扣住 X，X 自己又拥有一根活动扣扣住 Y。必须先处理 Y 的连接，再解除 X 的上游约束，才能继续相应中心的释放。该结构属于真正的二层依赖，不改变单缺口、真实旋转、实体阻挡和两类锁杆规则。

实现文件：`src/formal-relays.js`。采用人工校验后保存的固定清单，`src/formal-mechanisms.js`在离线掩码构建后应用；运行时只读取预存关系，并不枚举/搜索候选。

## 接力覆盖范围

共30个正式关卡：

`13, 15, 23, 24, 25, 27, 28, 29, 30, 31, 33, 35, 38, 39, 40, 43, 44, 49, 50, 51, 52, 53, 55, 56, 58, 63, 65, 71, 73, 74`。

每关新增一根真正固定在原接收镯上的活动锁杆，同时新增一个合法保持/脱扣阶段。背景固定扣仍固定于玉盘且保留另一端生命期。因为活动扣插入到背景杆之前，所有受影响的背景杆编号和预定提示阶段 claspId 已同步顺延；解法从修改后的提示阶段重新计算。

接力关修订号`revision:3`；只有五类掩码调整的关仍为`revision:2`；正式第1关（revision 2）、正式第2—10关（revision 1）以及第45关不变。局内存档版本失配时重新开局，但通关历史成绩和星级应继续保留。

## 验证结果及边界

- 由现有权威物理计算中的几何、端点、连续旋转、阻挡、消除规则制作的本地等价规则驱动器完成89个掩码关的预设路线检查：全部成功，0个残局留镯；其中30个接力关有额外活动扣。
- 30/30接力关完成初始几何、活动扣归属、阶段目标、解法扣号一致性与前后中心释放顺序检查。
- 对30个接力关逐批验证了提示目标向量与逐阶段解扣方向；已测试的接力关均顺利完成全程提示路线。
- 完整测试所需的更严格断言已提交在`tests/relays.test.mjs`。已修改旧版断言，使其识别修订号3和每个接力关新增的一根活动扣，同时不降低双背景扣死锁、保持组和多镯相邻连通性的校验。
- **尚未在完整工程安装依赖后执行`npm run test:fast`/`npm test`，也未进行Playwright真实浏览器手势、Android/iOS真机和自动广告/存档接入验收**。本地等价驱动器并不能代替完整编译及端到端测试。

## 暂不做的内容

- 不改变第1关或10个教学关。
- 不随机制造双向环形所有权或多个背景固定扣同时扣住同一单缺口镯；这类结构可能永久不可解。
- 不将线性提示阶段直接声称为通用分支DAG。未来的多分支谜题要重新设计依赖和提示回退逻辑。
- 不在完整工程回归与浏览器自测通过前合并main或部署预览库。

## 最终合入条件

1. 完整依赖环境`npm run build`及`npm run test:fast`通过。
2. `npm test`含100关权威连续碰撞通关、提示状态回退、存档工具操作均通过。
3. 移动端真实手势抽样验收：第13、25、40、50、74、100关，含提示手指不随环转、锁扣吸附、手势阻挡和局内恢复。
4. 仍不能完成的物理/提示/存档问题必须先修复，再更新Draft PR状态。
