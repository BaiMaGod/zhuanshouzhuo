## 0. 规则冻结

- 第100–109关均109只；第110关起每关镯数=关卡编号。只实施101–200新关，保留第100关现有实现与统计。
- 101–130只有爆裂属性；131–160只有缠丝属性；161–170两者同场但不能同镯；171–200允许复合镯。普通镯可存在于所有阶段。
- 背景三/四/五/六头扣分别从111/131/171/191开始；每件背景扣固定于玉盘，端点分别读取不同目标镯；所有端目标消除后才整件消失，或被爆裂实际命中时按整件扣ID震断退出。
- 挂载活动扣始终固定在Owner镯，随它旋转，必须有合法Receiver。目标消除时，Owner尚存则杆体仍保留，目标端套扣失效；Owner消除时整根所属杆消失。已对齐再转离可重新扣合，不累计“永久解锁”。
- 爆裂**实际消除后**才震断**真实相邻**镯上的有效扣件；若因此引起另一爆裂镯实际消除才允许接续；不得因为仅被爆裂命中就自动消除，更不能直接减少缠丝层数。
- 缠丝层数只能由不同、真实相邻、实际被消除的来源镯分别贡献1层；先解丝，后仍须满足普通锁扣条件。复合镯先解丝、再解扣、实际消除后才爆裂。
- 105、110、115……200 共20个限时关；第一次主动旋转才开始倒计时，设置/提示演示/道具弹窗暂停，超时立即失败。末镯逻辑解除时间不晚于截止时刻才通关，动画时长不延后成功判定。

## 1. 真正可执行的最小实体契约

下列键建议导出为机器可读 JSON。每关ID只在本关唯一，引用需要加关卡上下文。当前Excel里的M杆件ID、F端点ID是**结构占位编号**，不等于几何已定：

| 实体 | 必填 | 规则 |
|---|---|---|
| `level` | `level, ringCount, rings[], mountedRods[], backgroundPieces[], silkEdges[], burstTargets[], verifiedRoute, validation` | 可执行以前，数组之间必须完成交叉引用 |
| `rings[]` | `id, attribute, silkLayers, center{x,y}, radius, ringWidth, gapLocalAngle, initialRotation` | 圆心和完整碰撞外缘在玉盘可用范围 |
| `mountedRods[]` | `id, kind:'ringMounted', ownerId, receiverId, anchorLocal{x,y}, angleLocal, length, endpointWidth` | receiver不得为空、自连或指向不存在的镯；每根杆件用唯一ID，随owner变换 |
| `backgroundPieces[]` | `id, kind:'backgroundFixed', anchorWorld{x,y}, branchPaths, endpoints[]` | 2–6端；整件固定在玉盘；各端目标不同，且初始每镯不超过1个背景端点 |
| `endpoints[]` | `id, receiverId, endpointWorldAngle, endpointWidth` | 初始必须贴合实际目标镯边缘与缺口规则，不悬空不穿模 |
| `silkEdges[]` | `sourceId, targetId, validatedAdjacent, triggeredBy:'actualRemoval'` | 同一source-target组合去重，来源消除才减层 |
| `burstTargets[]` | `sourceId, targetRingId或pieceId, validatedAdjacent, resolvedByPieceId` | 候选需经布局实测；命中背景扣按整个pieceId去重 |
| `verifiedRoute` | `initialStateHash, orderedSteps[], finalStateHash, replayReport, stepsS` | 每步有连续旋转路径/实际事件，不能直接赋目标角、越障、调用道具或假定消除 |
| `validation` | `staticIntegrity, connectivityComplete, geometryVerified, sweepVerified, fullRouteVerified, difficultyVerified, mobilePlaytested, publishReady` | 除已经执行的静态数量检查外全部保持false |

**缺失值不能默认0、猜Receiver或按“预计前置”直接补边。** 旧表的“其他预期前置ID”只是局部设计意图，不是有效活动锁扣完整Owner→Receiver连接；“爆裂关键邻镯”也不是已证实的物理邻接。

## 2. 结构门槛（自动检查，全部适用于101–200）

1. `ringCount = len(rings) = sum(M0..M6) = ordinary+burstOnly+silkOnly+both`；`sum(i*M_i)=len(mountedRods)`。
2. `len(backgroundPieces)=sum(B2..B6)`，`len(all endpoints)=sum(k*Bk)`；同一件的端数、端ID和目标ID一致；背景接收目标不重复；所有跨表引用存在。
3. `sum(silkLayers)=len(silkEdges)`；每个目标的来源唯一且非自身；特殊镯分段合法；“缠丝”和“复合”不同条件单独校验。
4. 所有杆件Owner、Receiver和几何字段齐全且有限数；自带扣只能有一个Owner和一个Receiver，不能把挂载杆误存成背景杆。初始加载不自动清空。
5. 本次可编辑Excel的100关**只完成1–3中与已存在数据有关的静态检查**，因为mountedRods的Receiver与实际几何尚不存在；不能把这一通过标记提升为第4项通过。

## 3. 几何/状态验收（七关样板必须逐项执行）

- 真实玉盘安全轮廓内连续密铺，不人为拉开空隙；真实完整外缘、阴影、支杆都在有效区域。
- 背景支杆锚点和各端套扣必须位于实际可用空隙；三至六头扣逐端独立的扣合、脱扣和生命周期正确。
- owner杆体每个合法旋转区间连续扫掠验证；receiver旋转不带动别人杆体；对齐转离后依当前姿态重新扣合；残留杆件继续参与碰撞。
- 每次操作用实际引擎事件时间线审查：手镯消除、背景整件退扣、爆裂连锁、丝层减少、最后消除与UI结算一致；不得出现最后一步锁扣残影。
- 保存机器可读操作日志、场景状态Hash、冲突对象、旋转区间和失败原因。任何一次穿模、死锁或越界均退回设计。

## 5. 解法、难度和试玩验收

1. 真实解法器输出一条**无提示、无消除道具、连续合法旋转**的整盘路线；记录每一步操作镯、合法角度、受影响杆、碰撞检测、被消除镯与时间线，并在相同引擎中回放到0剩余。
2. 与既有第50–100关同口径记录：必要依赖深度、实际有效分岔、完整路线动作S、玩家实际拖动、最长同类连续操作、布局重复率。局部DAG层级和“支路数”不能替代实测。
3. 比较三种固定策略：优先当前可消除、优先爆裂、优先就近；记录相同种子下完成率、步骤成本和首次卡住的位置。简单策略可一路通关时须修改机关/布局而不是虚增数量。
4. 手机端实际完整试玩，观察触控误选、动效反馈、读扣难度与疲劳。技术自动测试通过不替代视觉/操作验收。
5. 以上所有环节通过后再允许标记 `publishReady=true`；未完成只写“待验证”。

## 6. 限时挑战严格门槛

`S` 必须来自无道具、完整路线的已验证操作步数，`T=5*ceil((S*t+H)/5)`。参数分段保持原方案：105–130 `t=3,H=20`；135–160 `t=3.5,H=25`；165–180 `t=3.5,H=30`；185–200 `t=3,H=30`。

初版时间只能在 `S` 已证实后计算；首次试玩目标成功率60%–70%，实测后再做约10%的调整并向上取整至5秒。正式关卡超时判失败，不能变为只扣星。当前20关S与时长均**待验证/待填写**，不能伪造具体秒数。建议采集不少于20名首次见到布局、熟悉机制的玩家进行首轮评估（样本门槛为此V2新增的**验收建议**，非旧版已经确认的正式规则）。
