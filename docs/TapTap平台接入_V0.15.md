## 无自建登录服务时的存档隔离

`tap.login` 的一次性 code 不是稳定账号 ID，不能用于本地键或跨设备匹配。当前由容器校验云档归属，本地存档按返回的 archive UUID 隔离：

1. 每次在容器启动时建立新的本地会话，保留原有试玩和历史账号数据，不自动上传。
2. 成功读取当前容器用户的存档列表，按固定槽名 `jade_save_v1` 过滤并取最新 `modifiedTime`。
3. 下载完整存档、校验全部结构后，切换到 `archive:<uuid>` 的本地空间；旧版服务端 owner 字段只在完整校验后迁移。不会信任客户端传入的 openid。
4. 本次启动期间刚产生的进度可合并；其他本地空间的进度需要玩家明确选择“导入本地进度”或“恢复本机进度”，导入的成绩不进入排行榜。
5. 当前用户无云档时不读取上一账号的缓存；本局首次上传创建槽位后，将本地空间转存到该 UUID，后续仅更新该槽。
6. 读取失败或结构无效时不上传覆盖；本局进度继续保存在独立本地会话。下一次成功连接后，可明确恢复本机未同步进度。未能识别账号时，不声称实现自动离线账号恢复。

本机恢复候选可能来自其他账号，界面在恢复前明确提示。最近16个空间保留在恢复索引中，底层原始本地键不删除。该 UUID 仅用于客户端数据隔离，不是服务端身份凭据或反作弊保证。容器内切换账号后应重新启动游戏以重新探测身份；没有接入未经文档确认的账号变更事件。

## 云档内容、合并和限频

存档包含教学与正式关永久进度、最好星级与步数、未完成正式盘面、免费道具余量、广告领取及剩余奖励、独立排行榜成绩。

- 永久进度、星级取较大值；最好步数取较小值；设置保留本机值。
- 盘面冲突先让玩家选择本地或云端整份盘面，不拼接手镯角度。
- 广告奖励沿用重开代次及领取/消耗记录的保守合并，避免旧云档恢复已消耗奖励；不对次数取最大值。
- 先 `writeFile` 到 `tap.env.USER_DATA_PATH`，再 `createArchive` / `updateArchive`。已有 UUID 更新失败仍保留 UUID，重试不得重复建档。
- 上传尝试至少相隔65秒；窗口内合并到最新本地状态，定时补传；失败65秒后重试。上传期间继续产生新修订时，不将新修订误标为已同步。
- 元数据使用英文槽名和短摘要，`extra` 只存修订号和时间，保持在1000字节以内。完整游戏存档可能超过元数据上限，因此继续通过官方 `getArchiveData` + `readFile` 下载，而非把整个存档塞入 `extra`。

## 广告与次数规则

每局免费提示1次、免费消除1次；广告提示和广告消除各限领一次。明确重开时恢复免费次数、重置两类领取资格并清空未用广告奖励。继续盘面时保留次数。

- 两种奖励共用一个平台激励视频实例，无需两个广告位。
- 只在 `onClose` 返回 `isEnded === true` 时发奖。中断、没有完成标志、加载失败、播放失败、超时都不发奖、不扣领取资格。
- 播放失败时最多主动加载并重试显示一次；失败后解除操作锁，保留真实错误码。1004显示暂无可播放广告，1005显示审核中，配置错误和其他错误分别提示。
- 重复回调只能结算一次；旧盘面广告回调不能给已切换或重开的新盘面发奖。广告期间拦截盘面操作。
- 不依赖登录状态、云档同步状态或自建服务。
