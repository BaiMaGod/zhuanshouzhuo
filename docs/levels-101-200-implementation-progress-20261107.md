## 七关样板仍不能进正式关卡

设计骨架中107、131、151、161、171、191、200共7关缺少数百条活动扣 Receiver、所有真实几何点/路径以及同引擎全盘合法通关回放。保留原稿为空，不用伪造直线、虚假邻接或一键清空来凑数。**编译器明确拒绝缺失的字段，避免将未验证的设计当成可玩关卡。**

当前还没有将它们插入`src/formal-campaign.js`或导出至`src/levels.js`。因此现有正式关卡仍是1–100，TapTap原包仍是0.15.16；任何构建产物只用于开发CI，不属于新的游戏发布包。

## 真正上架之前必须补足

1. 逐只准确的玉镯几何及Owner→Receiver活动杆件布线，背景多头支杆真实路径，符合玉盘安全轮廓和移动端可读尺寸。
2. 逐关完整物理走法，由当前`Core.request`连续旋转回放，验证不会穿模/死锁/开局误清空，保存日志与状态Hash。
3. 三种简单策略与50–100关难度比较，反复动作疲劳检验。
4. 真实手机测试、新机制表现、首次限时成功率校准，200关的S与倒计时秒数明确后再开放。
5. 修复新模块所有CI失败并核对前100关测试；视觉与触控验收独立于自动化技术测试。

**当前实现的是可选机制运行层 + 发布阻断，不是7个样板关已完成。**

## 调用方式

```bash
npm ci
npm run levels:verify-advanced -- ./path/to/filled-and-verified-seven-samples.json
```

**注意**：当前7关骨架仍包含空值，调用上述命令应该明确失败，直到真实几何与合法动作列表齐全。状态哈希采用`scripts/verify-advanced-samples.mjs`中的规范化JSON结构进行SHA256计算，不能用随机字符串伪造。原来的100关与教学关完全不依赖该脚本。
